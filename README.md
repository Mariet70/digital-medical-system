# Digital-medical-system
My Internship project
This project is the backend of our Digital Medical System, built using Node.js, Express, and a PostgreSQL database hosted on Supabase. So far, I have set up the backend server, connected it successfully to the database, and created basic API routes to test the connection and handle simple user data. I also configured environment variables using a .env file and made sure sensitive information is not pushed to GitHub by using a .gitignore file. Along the way, I faced several challenges such as Git not being available on my school laptop, working in the wrong directory, environment variables not loading properly, and multiple database connection errors caused by incorrect connection strings, wrong regions, and confusion between direct and pooler connections in Supabase. After debugging step by step, I was able to fix these issues and get a working connection. This progress has now been committed and pushed to GitHub so that my teammates can access and continue working on the project.

## Authentication Implementation Update 
In this stage of the project, I implemented the backend authentication system for the Digital Medical System using Express, PostgreSQL (Supabase), bcrypt, and JWT. I created user registration and login endpoints, enabling secure password hashing and token-based authentication for different user roles such as patient, doctor, and admin. During implementation, I faced several challenges, including database connection errors, environment variable loading issues, duplicate code in the authentication routes, and localhost connection problems caused by incorrect PostgreSQL configuration. After debugging and restructuring the database connection into a separate shared db.js file, the authentication system was successfully tested using curl, confirming that user registration and login now work correctly.

# Frontend Implementation
The frontend implementation of the Digital Medical System was developed using React to provide a user-friendly interface for interacting with the backend healthcare management system. The purpose of this implementation was to transform the backend APIs into a functional web application that patients and doctors can use through a browser.
Several frontend pages were created to support the main features of the system. These include the Login page, Register page, Patient Dashboard, Doctor Dashboard, Appointments page, Medical Records page, Prescriptions page, and Messaging page. Each page was connected to the backend API so that users could interact with real data instead of static placeholders.
The login and registration features allow users to create accounts and securely access the system based on their roles as either patients or doctors. Role-based navigation was implemented so that users are redirected to the appropriate dashboard after logging in.
The patient dashboard allows patients to view important healthcare information such as upcoming appointments, medical records, prescriptions, and emergency contact details. The doctor dashboard provides summary statistics such as total appointments, pending appointments, unread alerts, and other useful information for managing patient care.
The appointments page was implemented to allow both patients and doctors to view appointment information. Doctors can also update appointment statuses directly from the frontend interface, making the demo interactive and practical.
The medical records and prescriptions pages allow patients to access their healthcare history in a clear and organized format. A messaging page was also implemented to allow communication between patients and doctors.
During development, some challenges were encountered. Issues with React file imports occurred because of incorrect file naming, but these were resolved by correcting the filenames. Frontend-backend connection problems were experienced due to GitHub Codespaces networking and CORS restrictions, but these were solved through configuration updates and proxy setup. Authentication token issues were also encountered during testing but were resolved through proper login session handling.
To improve the visual appearance of the system, a custom project logo was added to the frontend interface.
Overall, the frontend implementation was successfully completed and fully integrated with the backend, resulting in a working demo version of the Digital Medical System.
